+ 사용자가 대시보드, 미수료 현황, AI 검색, 직원별 교육 이수 체크 화면에 접속합니다.

+ 사용자가 직원별 교육 체크박스를 변경하면 백엔드가 교육 이수 기록을 저장하거나 수정합니다.
+ 변경된 이수 기록을 기준으로 미수료 현황이 다시 계산되어 화면에 반영됩니다.

### 🔶 핵심 로직

1) 직원별 대상 교육 자동 판별 <br/>
직원의 부서와 입사 유형을 교육 과정의 대상 조건과 비교해, 직원이 들어야 하는 교육을 자동으로 판별합니다.

+ `targetDepartment`가 ALL이면 모든 부서의 직원에게 적용됩니다.
+ 특정 부서가 설정되어 있으면 해당 부서의 직원에게만 적용됩니다.
+ `targetHireType`이 `ALL`이면 모든 입사 유형의 직원에게 적용됩니다.
+ `targetHireType`이 `신입` 또는 `경력`이면 해당 입사 유형의 직원에게만 적용됩니다.


<br/>
<br/>


2) 교육 이수 기록 기반 미수료자 자동 추출 <br/>
직원별 대상 교육과 교육 이수 기록을 비교해 아직 수료하지 않은 직원을 자동으로 추출합니다.

+ `COMPLETED` 기록이 있으면 수료자로 판단합니다.
+ `NOT_STARTED`, `IN_PROGRESS` 또는 이수 기록이 없으면 미수료자로 판단합니다.
+ 직원별 대상 조건과 이수 기록을 함께 확인해 미수료자 목록을 반환합니다.

<br/>
<br/>


3) 체크박스 기반 교육 이수 상태 관리 <br/>
직원별 교육 현황 화면에서 체크박스를 변경하면 해당 직원의 교육 이수 기록이 저장되거나 수정됩니다.

+ 체크하면 해당 교육을 `COMPLETED` 상태로 반영합니다.
+ 체크를 해제하면 `NOT_STARTED` 상태로 반영합니다.
+ 변경된 기록을 기준으로 직원별 교육 현황과 미수료자 목록을 다시 갱신합니다.

<br/>
<br/>


4) Fake AI 기반 자연어 검색 <br/>
사용자가 입력한 자연어를 FakeAiClient가 검색 조건으로 변환하고, 백엔드가 해당 조건에 맞는 교육 과정을 조회합니다.

+ `FakeAiClient`는 자연어에서 부서, 입사 유형, 카테고리, 필수 여부 등의 조건을 추출합니다.
+ 검색 조건만 변환하며, 실제 데이터베이스 조회는 백엔드에서 수행합니다.
+ `AiClient` 구조로 분리해 추후 실제 AI API로 교체할 수 있도록 구성했습니다.

### 🔶 Codex 개발 방식

1) Codex CLI 활용
+ Codex CLI를 사용해 프로젝트 생성, 기능 구현, 테스트 실행, 코드 검토 과정을 진행했습니다.
+ 작업을 한 번에 크게 요청하지 않고, 백엔드 도메인 설계, API 구현, 프론트 화면 연결, 테스트, 리뷰처럼 단계별로 나누어 진행했습니다.
+ 구현 담당, 테스트 담당, 리뷰 담당 역할의 하위 에이전트를 설정해 작업 결과를 검토하도록 했습니다.
+ Codex가 생성한 결과를 그대로 사용하지 않고, 요구사항에 맞는지 확인한 뒤 다음 작업 범위를 다시 지시하는 방식으로 개발했습니다.

<br/>
<br/>

2) 하위 에이전트 활용
+ Backend Worker는 Spring Boot 기반 도메인, API, Service 로직 구현에 사용했습니다.
+ Frontend Worker는 React 화면 구성과 API 연동 작업에 사용했습니다.
+ Reviewer는 코드 수정 없이 비즈니스 로직, API 응답 구조, 테스트 누락 여부를 점검하는 역할로 사용했습니다.
+ Tester는 백엔드 테스트와 프론트엔드 빌드 결과를 확인하는 역할로 사용했습니다.


```
[ Codex CLI 작업 요청 예시 ]

직원별 교육 이수 상태 패널을 추가해줘.

요구사항:
- 직원은 한 번에 5명씩 보여줘.
- 직원의 부서와 입사 유형에 맞는 교육만 표시해줘.
- 교육 옆 체크박스로 수료 여부를 변경할 수 있게 해줘.
- 체크 상태가 바뀌면 교육별 미수료 현황도 다시 갱신해줘.

백엔드:
- 직원별 교육 이수 상태 조회 API를 추가해줘.
- 교육 이수 상태 변경 API를 추가해줘.

프론트엔드:
- /incomplete 화면에 직원별 교육 이수 상태 패널을 추가해줘.
- 체크박스 변경 성공 후 미수료 현황을 다시 불러와줘.

주의:
- 기존 Dashboard와 AI 검색 화면이 깨지지 않게 해줘.
- 필요한 최소 변경으로 구현해줘.
```
```
Reviewer 에이전트로 현재 구현 상태를 검토해줘.

검토 기준:
- 직원의 부서와 입사 유형에 맞는 교육만 연결되는지 확인해줘.
- COMPLETED 기록이 있으면 수료자로 판단되는지 확인해줘.
- NOT_STARTED, IN_PROGRESS, 기록 없음이 미수료로 처리되는지 확인해줘.
- 체크박스 상태 변경 후 미수료 현황이 다시 계산되는지 확인해줘.
- API 응답에서 Entity를 직접 반환하고 있지 않은지 확인해줘.
- 테스트가 부족한 부분이 있는지 정리해줘.

주의:
- 코드는 수정하지 말고 리뷰 결과만 정리해줘.
- 문제가 없다면 문제가 없다고 명확히 말해줘.
- 수정이 필요하다면 우선순위 순서로 정리해줘.

```

### 🔶 개선 방향

+ 현재 Fake AI로 구현한 자연어 검색을 `AiClient` 구조를 유지한 채 실제 AI API 기반 검색으로 확장할 수 있습니다.
+ H2 Database로 구성한 개발용 데이터를 MySQL 같은 운영 DB로 전환할 수 있습니다.
+ 교육 과정 등록, 수정, 삭제 기능을 추가하면 HRD 교육 관리 기능을 더 확장할 수 있습니다.
